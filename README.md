## Day 3: ADC 与模拟信号采集基础

**学习目标：**
- 搞懂模拟信号（连续电压）与数字信号（0和1）的区别。
- 理解 ADC（模拟-数字转换器）的工作原理。
- 学会使用 `analogRead()` 读取 0V~3.3V 的电压，并在串口监视器中实时查看。

**Wokwi 电路搭建：**
- 核心元件：ESP32 开发板 + 电位器（Potentiometer，模拟传感器输出）。
- 接线逻辑：
  - 电位器 VCC -> ESP32 3V3
  - 电位器 GND -> ESP32 GND
  - 电位器 SIG (中间引脚) -> ESP32 GPIO 34 (仅输入引脚)

**代码核心逻辑：**
- `int sensorValue = analogRead(34);` // 读取 0~4095 的整数（ESP32 是 12位 ADC）
- `float voltage = sensorValue * (3.3 / 4095.0);` // 将数字读数换算为实际电压（0V~3.3V）
- `Serial.print(...)` // 将读数与电压值输出到串口监视器

**实际运行与排错记录：**
- 现象：点击运行时，Wokwi 提示 `Build Servers Busy` 或 `Failed to fetch`。
- 定位：这是 Wokwi 免费编译服务器排队/网络连接失败，并不是本地代码或电路错误。
- 结果：等待并重试后，成功运行。拖动电位器旋钮，串口成功滚动输出 `ADC Read` 与 `Voltage` 数据。
- 经验总结：第一次接触到 Windows 与 Linux 的换行符差异警告（LF will be replaced by CRLF），虽然看似报错，但不影响代码运行。

## Day 5: 移动平均滤波 (Moving Average Filter) 与噪声模拟

**学习目标：**
- 理解噪声对信号采集的影响。
- 掌握“滑动窗口（环形缓冲区）”算法，实现高效的移动平均滤波。
- 理解嵌入式信号处理中“平滑度与响应延迟”的权衡。

**实验过程与核心发现：**
1. **理想与现实的差异**：在 Wokwi 模拟器中拖动电位器，发现 `Raw` 原始值完全没有跳动（因为模拟器是理想化的）。这让我意识到，真实世界中的热噪声和电磁干扰（如50Hz工频干扰）在纯软件模拟中是不存在的。
2. **人为注入噪声**：为了模拟真实的脑机接口采集环境，我修改了代码，通过 `random(-20, 20)` 手动为 ADC 读数注入了高频随机噪声。
3. **验证滤波效果**：在注入噪声后，`Raw` 值开始剧烈跳动，而经过滑动窗口计算出的 `Filtered` 值依然保持平滑稳定。
4. **工程权衡**：尝试将窗口大小从 10 增加到 50，发现滤波值更加平滑，但跟随手动调节的延迟也显著增加。理解了“滤波强度越大，响应越慢”的底层规律。

## Day 7: 峰值检测与 BPM 估算

**学习目标：**
- 理解基于时间差（Time Difference）计算频率的底层逻辑。
- 掌握峰值检测（Peak Detection）算法，实现单次动作的精准触发。
- 了解嵌入式防御性编程（防止除以零导致程序崩溃）。

**核心代码逻辑：**
- **模拟信号生成**：利用 `millis() % 1200 < 300` 配合 `random()` 函数，模拟每 1.2 秒出现一次的高幅值信号（模拟心跳/眨眼，即 50 BPM）。
- **时间差计算**：在检测到两次连续峰值时，记录它们之间的毫秒差 `timeDiff = currentTime - lastPeakTime`。
- **频率换算**：利用公式 `BPM = 60000 / timeDiff`，将时间间隔转换为每分钟的次数。
- **状态机防抖**：使用 `isPeakDetected` 标志位，确保一次信号爆发只触发一次计算，避免重复触发。
- **防御性编程**：加入 `if (timeDiff > 0)` 的判断，防止由于极短时间内的连续触发导致 `timeDiff` 为 0 时发生除零错误（崩溃）。

**实际运行与排错记录：**
- 成功在串口监视器中观察到每 1.2 秒打印一次 `>>> 检测到峰值！当前频率: 50 BPM <<<`。
- 理解了 `millis()` 函数的返回类型以及为什么必须使用 `unsigned long` 存储时间戳。
- 成功实现了 LED 闪烁与 BPM 计算并行运行，互不阻塞。

## Day 8: 无线数据传输 (从 BLE 受挫到 Wi-Fi UDP 成功)

**学习目标：**
- 了解脑机接口设备从“有线串口”走向“无线传输”的必要性。
- 掌握 ESP32 的 Wi-Fi 连接与 UDP 数据包发送逻辑。
- 理解不同无线通信协议（蓝牙 BLE 与 Wi-Fi）在脑机接口场景下的工程权衡。

**实验过程与踩坑记录：**
1. **尝试蓝牙 (BLE)**：
   - 编写了 BLE 服务器和特征值（Characteristic）的初始化代码，并尝试通过“通知 (Notify)”机制发送数据。
   - **遇到大坑**：Wokwi 模拟器的虚拟蓝牙协议栈在初始化时（`BLEDevice::init()`）直接崩溃，触发了“看门狗（Task Watchdog）”强制重启。即使重建项目、精简代码，依然卡在初始化阶段。
   - **技术复盘**：Wokwi 在浏览器中的模拟内存有限，无法承载庞大的蓝牙协议栈，且蓝牙初期调试遇到 Wokwi 模拟器的严重兼容性问题。
2. **战略转向 Wi-Fi (UDP)**：
   - 由于脑机接口（尤其是多通道、高采样率的原始数据流）需要极大的带宽，Wi-Fi 在真实工程中反而是更合适的方案。
   - 放弃蓝牙模拟，改用 Wi-Fi UDP 方案，代码逻辑瞬间顺畅，模拟器极其稳定。

**核心代码逻辑与结果：**
- **Wi-Fi 连接**：使用 `WiFi.begin("Wokwi-GUEST", "")` 成功连入虚拟 Wi-Fi 网络，并通过 `WL_CONNECTED` 状态判定连接成功，获取本机 IP（`10.10.0.2`）。
- **UDP 发送**：利用 `WiFiUDP` 对象，通过 `beginPacket()` -> `print()` -> `endPacket()` 三步，将模拟的 BPM 数据以无线方式发送出去。
- **视觉反馈**：LED 灯以 0.5Hz（2秒一个周期）的频率闪烁，完美指示着系统的心跳，同时不影响数据包的无线发送。
- **实际效果**：串口监视器成功打印出 `已通过 Wi-Fi 发送: BPM: 1, 2, 3...`，实现了真正的无束缚无线传输。

- 掌握混淆矩阵（Confusion Matrix）的绘制与业务解读。
- 解决因环境或库版本更新导致的 API 冲突问题。

**核心算法与数据流：**
1. **数据切片**：使用 `mne.Epochs` 将连续的 EEG 数据按事件（T0休息, T1左手, T2右手）切分为 4 秒长的独立样本。

3. **模型训练**：将数据集按 70%（训练集）和 30%（测试集）划分，使用 `RandomForestClassifier` 训练模型。
4. **性能评估**：模型在测试集上达到了 **77.78%** 的预测准确率。通过 `ConfusionMatrixDisplay` 生成 3x3 混淆矩阵图，直观展示模型对“休息、左手、右手”三种意图的分类表现。

## Day 18: 跨受试者泛化（Cross-Subject）的“滑铁卢”与反思

- 尝试合并 5 名受试者的数据，构建大样本集，以训练深度学习模型。

**实验过程与核心技术：**
1. **EA 魔法**：通过计算每个受试者数据的协方差矩阵并求逆平方根，强行将不同个体的脑电波分布“揉捏”到统一的标准空间，极大降低了跨受试者的物理差异。
2. **全局随机打乱**：将 5 名受试者经过滑动窗口增强后的样本混合在一起，进行全局随机打乱并切分 80% 训练集 / 20% 测试集。

**实验现象与深度反思（“滑铁卢”）：**
- **虚假繁荣**：Loss 曲线平滑下降，但测试集准确率仅为 50.00%（甚至低于纯瞎猜）。
- **病因分析（数据泄露 Data Leakage）**：因为滑动窗口的步长是 0.2 秒，窗口是 1.0 秒，相邻两个样本有 80% 的波形是重合的。全局随机打乱后，高度相似的样本被分到了训练集和测试集。模型通过“死记硬背”在训练集里见过测试集的数据，导致严重过拟合，无法反映真实的泛化能力。

## Day 25: 个体微调（Fine-tuning）与迁移学习的“翻车”反思

**学习目标：**
- 掌握迁移学习（Transfer Learning）在 BCI 领域的标准落地流程。
- 实现基于“冻结主干网络，微调分类层”的个体校准（Calibration）策略。

**实验设计与核心代码：**
1. **基础模型**：使用 1、2、3、4 号受试者训练 EEGNet。
2. **冻结特征层**：设置 `requires_grad = False`，锁住负责特征提取的卷积层，防止“灾难性遗忘”。
3. **微调决策层**：仅解冻 `fc` 全连接层，使用受试者 5 的 20% 数据（模拟个体校准集）进行 20 个 Epoch 的微调。

**实验现象与深度反思（实验结果“翻车”）：**
- **反常结果**：模型在受试者 5 身上的准确率，微调前为 56.00%，微调后不升反降，跌至 52.50%。
- **病因剖析**：
  1. **严重过拟合**：受试者 5 的校准集样本量过小（仅 20%），模型在 20 个 Epoch 下“死记硬背”了小样本特征，丧失了泛化能力。
  2. **基础模型偏弱**：受试者 5 本身的脑电特征（BCI-Illiteracy）就不明显，基础模型本就在“瞎猜”。
  3. **类别不平衡**：小样本校准集可能存在严重的类别偏移（左手或右手样本数量悬殊）。
- **科研结论**：微调（Fine-tuning）绝非万能。在样本量极小且受试者特征极弱的情况下，强行微调会导致模型崩溃。这深刻提醒了我们个体校准设计的严苛性。

## Day 27: 跨受试者泛化极限测试与领域偏移反思

**实验目的：**
- 更换受试者（Subject 2），并使用 9 人联合训练，验证微调（Fine-tuning）能否突破跨受试者瓶颈。

**实验现象：**
- 受试者 2 盲测基准准确率仅为 51.33%，微调后为 50.83%（等同于随机瞎猜）。
- 受试者 10 盲测基准为 52.67%，微调后为 57.50%。

**深度科研反思：**
1. **深度学习在跨受试者上的脆弱性**：EEGNet 提取的空间特征（如固定的 C3/C4 权重）极度依赖个体解剖结构。面对全新的受试者，它的卷积核相当于“刻舟求剑”，完全失效。
2. **数据处理陷阱**：在 EA 对齐后，如果再次进行全局 Z-score 标准化，会破坏数据的相对分布特征。
3. **个体差异（Domain Shift）**：这是真实 BCI 最大的壁垒。工业界若要解决此问题，通常不依赖纯时域 EEGNet，而是采用：
   - 传统的 CSP 空间滤波算法结合 SVM。
   - 包含大量频域（PSD）特征的混合模型。
   - 基于对抗学习的领域自适应（Domain Adaptation）网络。

## Day 24: 严苛的跨受试者盲测与 EA 魔法

- 彻底修复了随机打乱带来的“数据泄露”问题，实现了严格按受试者切分（Train on 1,2,3,4 -> Test on 5）。
- 引入了 **欧几里得对齐 (EA)** 算法，极大缩小了不同受试者之间的脑电分布差异。
- 加入了更严谨的标准化（仅用训练集均值和方差）以及防过拟合策略（Dropout=0.5 + L2 正则化）。
- **实验结果**：在完全未见过的受试者 5 身上，取得了 **62.67%** 的真实盲测准确率，这证明了模型成功学到了跨人的通用特征，且 EA 算法起到了决定性作用。
